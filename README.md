# Fantastic Android

[Fantastic](https://github.com/kid141252010/Fantastic) 的安卓客户端。在手机上搜歌、听歌、看歌词。

歌不在这个 App 里。先准备好自己的 Fantastic 服务器，打开后把地址填进去。能搜到什么、能播什么，取决于那台服务器和上面的账号。这个 App 不收集、也不发送网易云 Cookie。

Android 8.0 及以上可以安装。

## 亮点

- **一个搜索，三个音源。** QQ 音乐、Apple Music、网易云。歌曲、专辑、艺人、歌单都能点开听，从你点的那首开始。
- **Apple Music 搜索选区。** 搜索框右侧地区与设置共用同一选择；新安装默认 `ca`，已有选择不变。菜单列出全部 Apple Music 地区，服务器报告 wrapper 支持的排在前面并标注，未标注地区也能搜索。
- **歌词跟着唱。** 歌词画在手机上，唱到哪个字，哪个字亮。翻译和音译可以单独打开。对唱左右分开，背景人声单独显示。看歌词时屏幕保持亮着。
- **播放器拉上来就能用。** 底部是正在播放的小条。展开后有封面、歌词和接下来要播的歌，收起来音乐继续。再打开还是上次看的那一页。
- **资料库在手机上。** 可以建歌单和文件夹，收藏，导入和导出。想离线听，在菜单里下载，到「资料库 → 已下载」播放。下载的歌不会被播放缓存清掉。
- **资料库曲序与偏好。** 库内专辑只播放已保存的歌曲，按可信的碟号、曲号或专辑参考顺序排列；缺号保留未知，不把库内子集重新编号。已知在线总数大于库内曲目数时，列表尾部提供「显示完整专辑」，查看不会自动入库。歌曲、专辑和艺人的标题/最近添加排序分别记忆；「设置 → 资料库 → 显示音源来源」即时生效并在重启后保留。首页大标题随列表滚走，由浮动操作入口接管；点击底栏返回目标标签一级页，同标签搜索保留关键词和音源。
- **Apple Music 可以逛。** 「新发现」和「广播」用来找内容和电台。音质、空间音频和切歌方式在设置里选。

听过的在线歌曲会在手机里留一份，下次不用整首重下。缓存满了，先清最久没听、也没在用的。大小在设置里改。Apple Music 如果开了自动混音、交叉淡化，或者这首歌只能用网页播放，就继续在线播。

关掉再打开，歌、进度、待播顺序、随机和循环都还在，但不会自动接着播。

QQ／网易云专辑的首次有效总数和真实曲序参考保存在同一份本地资料库中，也随导出／导入保留。重进和重启后直接使用，不自动刷新；参考歌曲不会自动加入收藏或播放队列。总数缺失、请求失败仍保留重试；保存失败会在本地专辑页提示，不能保证重启后免读取。

Apple 资源保留实际取得它的 catalog 国家；后续目录、分享、队列、播放缓存和下载使用该来源，不因修改全局偏好而重标。历史文件中无证据的孤立 `country=us` 读为未知，歌曲仍保留，后续同资源真实响应才补齐。歌词和媒体解密的服务接口没有地区参数：客户端按地区隔离本地结果，不承诺控制服务端媒体账户地区。

主页现在还是空的。找歌用底部的「搜索」。设置在主页右上角。

## 安装

每天构建的安装包在 [Nightly](https://github.com/kid141252010/Fantastic-Android/releases/tag/nightly)，文件名是 `fantastic-debug.apk`。这是预发布调试包，不是应用商店的正式版。签名固定，新包可以直接盖住旧包。

1. 装上并打开。
2. 主页右上角进入设置，填写 Fantastic 服务器地址，点「检查并保存服务器」。
3. 去「搜索」选音源，搜一首歌播放。

地址要是完整的 `http://` 或 `https://`，不要带账号和问号后面的参数。明文 HTTP 只建议在局域网里用。

Apple Music 地区目录和 wrapper 支持地区按服务器保存在手机内。启动只获取没有成功缓存的数据；已有成功数据没有有效期，重开页面或重启不会刷新。设置页只显示缓存的 wrapper 支持地区；点「检查并保存服务器」仍会更新两路缓存，一边失败保留那边上次成功数据，wrapper 标记不代表当前实时健康状态。本次检查返回有效的 Fantastic /status 后立即保存服务器地址，不再依赖 AM 目录结果，也不会自动改选地区。地区输入规范为两位小写字母后即保存；若已有 wrapper 支持地区缓存，则仅接受缓存包含的地区，未知时只校验格式。其他设置在选择或合法输入时自动保存，歌词语言或字形清空时恢复默认值，关闭设置无需保存。切区保留搜索词和分类，关闭旧区 Apple 详情并重载发现内容，不主动重启当前播放。

## 本地字体打包

可选字体只从 Git 忽略的 `.work/local-am-fonts/assets/am-fonts/` 读取，不随源码或公开 CI 分发，也不在构建时下载。该目录需同时包含 `sf_pro_android_ui.ttf`、`sf_pro_rounded_android_ui.ttf`、`pingfang_ui_vf.ttc`、`hiragino_sans.ttc` 和 `apple_sd_gothic_neo.ttc`；现有其他语种字体可继续放在同一目录。来源说明须放在同一资产根目录的 `licenses/pingfang-ui-vf.txt`，随本地 APK 打包。

按 [Apple 的 CJK 字体建议](https://support.apple.com/zh-cn/guide/pages/tanfbd4156e/mac)，Android 10 及以上的界面和歌词共用 SF Pro 与 CJK 回退链：简体中文用苹方-简、台湾繁体用苹方-繁、香港和澳门用苹方-港，日文用无衬线 Hiragino Sans，韩文用 Apple SD Gothic Neo。应用语言决定汉字字形与回退顺序；苹方 UI 使用自身的 `wght`（100–900）和固定 `wdth=100`，不传 SF 的 `opsz`。请求字重优先，并补齐真实 400/700 实例供常规/粗体 run 选择；日文和韩文保留完整静态字重家族。Android 8–9 的 CJK 继续使用系统字体。

本地苹方来自 [ACT-02/PingFangUI-VF 的 21.4d1e1 版本](https://github.com/ACT-02/PingFangUI-VF/releases/tag/21.4d1e1)附件 `PingFangUI.tahoe.26.4.1.wght.wdth.ttc`。输入 SHA-256 为 `d1705d6a5e8e4c5981ec39ffd12effb7854c8bd4c20b5dba7e2db922f558e7c7`；使用 fontTools 4.68.0 的 `TTCollection`，以 `lazy=True, recalcBBoxes=False, recalcTimestamp=False` 载入，保存前仅保留 face `[0,1,2,4]`，并以 `shareTables=True` 保存为 `pingfang_ui_vf.ttc`。输出为 69,647,704 bytes，SHA-256 为 `e8d6762532ee1aeb9239e67d0a8f487d61b000ebddfe63f0293552658b3b5197`，顺序为 SC/TC/HK/JA，物理移除 MO；JA 保留但不加入实际回退链。来源说明使用[固定上游 commit 的 README 原文](https://raw.githubusercontent.com/ACT-02/PingFangUI-VF/8a901f9d8820bf8752fa20ca9903a33c9f225bbc/README.md)，按其学习研究、非商业及附带来源条件使用；项目的 Apache-2.0 不替代字体使用条件。新库的轮廓、字宽和字符覆盖与旧静态苹方不同，部分字符可能依赖系统回退，不承诺像素相同或全字符无差异。

本机构建显式传 `-PincludeLocalAmFonts=true`，缺少任一必需字体或来源说明时停止构建；资产目录残留旧 `pingfang.ttc` 或 `pingfang_ui.ttc` 也会停止，需自行移至 assets 外，不同时打包。用 `-PincludeLocalAmFonts=false` 可构建纯系统字体包。TTC 在 APK 内不压缩，按集合共享只读映射；苹方家族按地区与请求字重缓存并跨字号共享，日文/韩文各自缓存完整静态家族。

## 字重设置

设置页的「字体字重」可分别调节正文、标题和歌词，范围为 100–900。滑块松手后按整数保存并生效，重启后保留；每一项可单独「恢复默认」，沿用原有样式，不改变字号、行高或字宽轴。此项是用户可选扩展，不宣称是 Apple Music 原版的设置入口或官方字重参数。

- 正文：正文/标签、列表文字、说明和播放器艺人等；标题：页面/分区/卡片标题及播放器曲名。显式加粗或中黑的标题也服从标题设置，不被固定的 `FontWeight` 覆盖。
- 歌词：主词、伴唱、译文和音译共用该值；修改时重建文本布局，但不重新加载歌词、不重置播放时钟。创作者署名与来源说明保留原有常规/粗体区分。
- 默认仍使用原有 `500→510`、`600→590`、`900→1000` 映射；自定义值按原值请求 SF 和苹方 VF，不再套用该映射。苹方的地区与字重缓存继续共享同一只读 TTC 映射；日文、韩文和系统字体按实际可用字重匹配，旧系统不保证连续字重显示。字体自然字宽或轮廓变化可能影响折行，不用改字号或压扁文字掩盖。
